## 1. A/B round 1 — `harness-rules-r1`

### Setup

ตัวแปรเดียว: มี/ไม่มี `DESIGN.md` + design block ใน `AGENTS.md` โจทย์: สร้าง section "Evidence" ของ Keshi Pomodoro (3 รูป + caption) 4 runs อิสระ (A1, A2 = control, B1, B2 = treatment), แชร์ `tokens.css`/CSS อ้างอิง/ข้อมูลโปรเจกต์เหมือนกันทุกไบต์ (พิสูจน์ด้วย `diff -r`)

รายละเอียดเต็ม: [PLAN.md](../../../design/ab/harness-rules-r1/PLAN.md)

### เมตริกอัตโนมัติ — 13 ตัว ตั้งก่อนเปิดผล

ทุกตัวผ่าน self-test (ยิงติด known-bad, เป็นศูนย์กับ known-good) ก่อนใช้จริง

**พบเมตริกนับผิด 1 ตัวระหว่างใช้จริง — แก้และเปิดเผยตามหลัก skill:** `questions` เดิมนับเฉพาะ markdown bullet 2 runs เขียนคำถามด้วยหัวข้อ `###` แทน bullet ได้คะแนน 0 ทั้งที่เขียนยาว 3.3–3.5 KB แก้ให้นับทั้งสองรูปแบบ และเพิ่ม `questionBytes` เป็น cross-check ที่ไม่ขึ้นกับรูปแบบ

### ผลเมตริก

```
metric                  A1      A2      B1      B2
rawHex/rawColorFn/inventedTokens/varFallback/important/
unverifiedClaims/hoverTransform/reducedMotion/
transitionAll/emoji                                    0 ทุกตัว ทุก run
mediaQuery               1       0       1       1
questions                6       8       6       7
questionBytes          3327    3062    3542    3864
bytes                  8771    8268   14673   11902
words                    82      73     163      78
```

**แยกเงื่อนไขได้จริงแค่ 2 ตัว:** `bytes`, `questionBytes` — ทั้งคู่คือ B (treatment) เขียนยาวกว่า ที่เหลือ **ไม่แยกเลยหรือคาบเกี่ยวกัน** รวม `unverifiedClaims` ที่เป็น 0 ทุก run (เมตริกไม่ผิด แค่ไม่มีใครทำผิดข้อนี้เลยในโจทย์ขนาดนี้)

### ทำไมหยุดก่อนให้เจ้าของจัดอันดับ

เปิดหน้า blind comparison (สุ่มป้าย W/X/Y/Z) แล้ว แต่เจ้าของบอกว่า **"ไม่รู้สึกว่าแตกต่างเลยสักอัน"**

ตรวจแล้วพบสาเหตุเชิงโครงสร้าง: **ทั้ง 4 run ได้ CSS ของกรอบ media frame เดิมชุดเดียวกันเป๊ะให้ reuse** (ตามกฎ "reuse ก่อน extract" ที่ทั้งสองเงื่อนไขมี) ส่วนที่กินพื้นที่สายตามากที่สุด — รูป, กรอบ, เงา, radius — จึง**เหมือนกันทุกตัวโดยการออกแบบ** สิ่งที่ต่างจริงคือรายละเอียดเล็ก (ตำแหน่ง caption, ฟอนต์หัวข้อ, เนื้อหา caption)

พอไล่ลึกไปที่ฟอนต์หัวข้อ พบว่ามันไม่ได้สุ่มไร้แบบแผน — **มีความสัมพันธ์กับเงื่อนไขจริง:**

```
W = B1 (treatment)  →  --type-family-display (Syne)
Y = B2 (treatment)  →  --type-family-display (Syne)
X = A2 (control)    →  --type-family-editorial (serif)
Z = A1 (control)    →  --type-family-editorial (serif)
```

treatment ทั้งคู่เลือก Syne, control ทั้งคู่เลือก serif — split ชัด 2/2

**คำเตือนที่ต้องพูดตรง ๆ:** ก่อนหน้านี้ในแชทผมบอกเจ้าของว่าฟอนต์ "สุ่มกระจายคนละฝั่งกับเงื่อนไขจริง" — **คำนั้นผิด** ตอนพูดผมยังไม่ได้เปิด mapping ดู พอเปิดดูจริงพบว่ามัน split ตรงกับเงื่อนไข 100% เป็นการแก้คำที่พูดไปก่อนหน้า

แต่ split ที่ชัดนี้ **ก็ยังสรุปไม่ได้ว่าเป็นผลจาก `DESIGN.md`** เพราะ **n=2 ต่อเงื่อนไข** — ถ้าฟอนต์ถูกเลือกแบบสุ่มไม่เกี่ยวกับเงื่อนไขจริง โอกาสที่จะได้ split สะอาดแบบนี้พอดีคือ ~33% (มี 6 วิธีแบ่ง 4 อย่างเป็นคู่ 2-2 มี 2 วิธีที่ตรงกับเงื่อนไข) ไม่ใช่เรื่องที่เป็นไปไม่ได้เลยที่จะเกิดจากบังเอิญ และ `DESIGN.md`/`AGENTS.md` **ไม่มีข้อความไหนบอกให้เลือกฟอนต์ไหน** (G2 ยังเปิดอยู่จริง) จึงไม่มีกลไกที่อธิบายได้ว่าทำไมถึง correlate — เป็น **finding ที่บันทึกไว้ ไม่ใช่ข้อสรุป**

**เหตุผลที่หยุดจริง คือทั้งสองข้อรวมกัน:** (1) ส่วนที่กินสายตามากสุดเหมือนกันหมดโดยตั้งใจ ทำให้ผลต่างที่เหลือเล็กเกินจะตัดสินด้วยตา และ (2) การถามให้จัดอันดับตอนนี้จะเป็นการขอให้ตัดสินด้วยรสนิยมเรื่องฟอนต์ ทั้งที่ typography (G2) ยังไม่ถูกตัดสินเป็นทิศทางเลย — ผลที่ได้จะวัดปนกันระหว่าง "กฎช่วยไหม" กับ "ชอบฟอนต์ไหน" ซึ่งเป็นคนละคำถาม

### Finding ที่เก็บไว้ได้จริงโดยไม่ต้องใช้รสนิยม

**1 ใน 4 runs (W = B1) ตรวจสอบข้อมูลที่ได้รับกับรูปจริงก่อนเขียน แล้วจับได้ว่าข้อมูลผิด:**

`PROJECT-FACTS.md` ที่ผมเตรียมให้บอกว่ารูปที่ 2 เป็นหน้า "Settings" — แต่รูปจริงคือหน้า timer เดิมที่เปิด panel วิทยุ (เกือบเหมือนรูปที่ 1) มีแค่ B1 ที่เขียน caption ตามสิ่งที่เห็นจริง ("Session controls — the same screen further into the session...") ส่วน A1, A2, B2 ก๊อปข้อความจาก fact file ตรง ๆ โดยไม่ตรวจกับรูป

น่าสนใจว่า**เกิดกับ treatment แค่ 1 ใน 2** ไม่ใช่ทั้งคู่ — จึงยังเป็นแค่สัญญาณ ไม่ใช่ pattern ที่ยืนยันได้จาก n=2

## 2. สิ่งที่เรียนรู้จากรอบนี้ (สำหรับรอบ A/B ถัดไป)

1. **ให้ CSS อ้างอิงชุดเดียวกันทั้งสองเงื่อนไข ทำให้ผลต่างที่วัดได้เหลือน้อยเกินไป** — ถ้าจะทดสอบว่ากฎช่วย "หน้าตา" จริง ต้องเลือกโจทย์ที่ reference CSS ไม่ครอบคลุมทุกอย่าง เปิดที่ให้ AI ตัดสินใจเองมากกว่านี้
2. **ต้องตัดสิน macro typography (G2) ก่อน** ถึงจะทำ blind visual ranking ได้อย่างมีความหมาย — ไม่งั้นความต่างที่เห็นจะเป็นสัญญาณรบกวนจากช่องว่างที่ยังไม่ตัดสิน ไม่ใช่ผลของกฎ
3. **Reveal mapping ก่อนถามจัดอันดับเป็นความผิดพลาดของผม** (ทำตอนปิดรอบ ไม่ใช่ตอนขอ ranking) — แต่ก็ทำให้พบสิ่งที่ตรวจไม่ได้จากเมตริกอัตโนมัติ (ฟอนต์ correlate กับเงื่อนไข, การตรวจสอบข้อมูลของ B1) ซึ่งมีประโยชน์สำหรับรอบถัดไป

## 3. Redirect ไปยัง macro direction

แทนที่จะไล่แก้ font/caption ในระดับจุดเล็ก เจ้าของขอให้กำหนดทิศทางภาพใหญ่ก่อน → **Round 13** ใน [DESIGN-DISCOVERY.md](../DESIGN-DISCOVERY.md)

สรุปสั้น: gallery ทรงกระบอก/สไปรัลเป็น North Star ของ landing (ของเดิม `cylinderGrid` เป็นความพยายามแรกแต่ยังไม่พอ), personality ทั้งเว็บ = ศิลปะ/มีจิตวิญญาณ/แปลก/เรียบหรู, โปสเตอร์ปกต้องทำใหม่ทั้งหมด (queue เป็น W1), ความแปลก/คาดเดาไม่ได้ต่อเนื่องจาก gallery เข้า case study แต่ evidence ต้องหาเจอเสมอ, จังหวะเล่าแบบ "รถไฟเหาะ", แต่ละโปรเจกต์ต้องมี gimmick ของตัวเองไม่ใช้ template เดียวกัน

รายละเอียดเต็มและ criteria ที่ตัดสินแล้ว: Round 13 + `DESIGN.md` §2.1 (A16–A22), §7 (G1/G4/G6 อัปเดต, G11 ใหม่), Open work items (W1, W2)

## 4. สถานะขั้น 5 ตามเกณฑ์แผน

| เกณฑ์จากแผน | สถานะ |
| --- | --- |
| ใช้ `design-ab-loop`, โจทย์ bounded, asset/reference/environment เดียวกัน | ✅ |
| ควบคุม code/tokens/model/settings/time budget เหมือนกัน | ✅ — พิสูจน์ด้วย `diff -r` |
| อย่างน้อย 2 independent runs ต่อเงื่อนไข | ✅ (4 runs รวม) |
| fresh reviewer ไม่ใช่ผู้สร้างรับรองตัวเอง | ✅ เจ้าของเป็นผู้ดู ผมยังไม่เปิดโค้ดก่อนเมตริก |
| Blind review เปรียบเทียบ adherence/regression/เวลา | ⚠️ **หยุดก่อนถึงขั้นนี้** — เหตุผลใน §1 |
| ไม่อ้าง statistical reliability จากตัวอย่างเล็ก | ✅ ย้ำ n=2 ทุกจุดที่มี correlation |
| จำแนกผล improved/regression/inconclusive | ✅ **inconclusive by design** — ไม่ใช่ "กฎไม่ช่วย" |
| pending owner acceptance ไม่ถูกนับว่าผ่าน | ✅ ไม่มีการอ้างว่า `DESIGN.md` ได้รับการพิสูจน์ว่าช่วย |

**ขั้น 5 ยังไม่ปิดสมบูรณ์** — รอบ A/B ที่แท้จริง (มี blind ranking) ต้องรอ macro direction (โดยเฉพาะ G2) นิ่งพอที่จะทำโจทย์ที่วัดผลได้อย่างมีความหมาย
