# Project banner playbook

รสนิยมและวิธีทำที่เจ้าของยืนยันแล้ว สำหรับทำ banner/ปกของโปรเจกต์ถัดไป
สรุปจากปก 2 ใบที่เจ้าของรับ: **ModeNote v7** (`modenote-cover-v7.webp`) และ **Veluma v4** (`veluma-cover-v4.webp`, 1 Oct 2026)
ที่มา: [ModeNote draft](2026-10-01-modenote-cover-v4-draft.md) §6c, [Veluma brief](2026-10-01-veluma-cover-v4-brief.md), [cover spec](2026-09-05-project-cover-spec.md) (ขนาด/การส่งงาน)

## 1. หลักที่ต้องผ่านก่อนอย่างอื่น

**เห็น 3 วินาทีต้องรู้ว่า "นี่คือแอป และเป็นแอปประเภทไหน"** feature และบรรยากาศมาทีหลัง

ทิศที่เจ้าของปฏิเสธแล้ว และเหตุผล:

| ปฏิเสธ | คำของเจ้าของ / เหตุผล |
| --- | --- |
| Veluma v4 full-bleed (รูปเต็มปก มี pane ลอยอยู่ ไม่มีกรอบหน้าต่าง) | "โล่งเกินไป ไม่แน่ใจว่ามันคือแอปหรือ poster" |
| ModeNote v6 (ตัวเลขเวลา "8:44" ตัวยักษ์) | ไม่รู้ว่าโปรดักต์คืออะไร ตัวเลขสื่อความหมายผิด |
| ModeNote v4–v5 (ข้อความเรียบร้อยบนพื้นเรียบ) | "ยังคล้ายเดิม" ไม่มีอะไรดังพอสำหรับห้อง gallery |
| v3 ของทุกโปรเจกต์ | ดู AI generate (DESIGN.md A18) ดูข้อ 4 |

## 2. โครงที่ใช้ได้ (ทั้งสองปกใช้โครงนี้)

```
┌──────────────────────────────────────────────────────┐
│ [logo จริง] Wordmark ใหญ่          ประโยคเดียว (ขวาบน)  │
│                                   แถบ "works with" เล็ก │
│ ┌──────────────────────────────────────────────────┐ │
│ │ หน้าต่างแอปจริง ใหญ่ ~90% ความกว้าง ไม่เอียง          │ │
│ │ (title bar จริง) render 2x อ่านได้ทุกตัวอักษร          │ │
│ │ มีจุดเด่นด้านภาพ 1 จุดในหน้าต่าง                      │ │
│ └──────────────────────────────── ล้นขอบล่างได้ ─────┘ │
└──────────────────────────────────────────────────────┘
   พื้น: gradient สีแบรนด์ + grain · ออร่าแสงอ่อนรอบหน้าต่าง
```

| องค์ประกอบ | กติกา |
| --- | --- |
| **หน้าต่างแอป** | เป็นตัวเอกของภาพ ใช้ UI จริงจาก renderer จริงที่ deviceScaleFactor 2 พร้อมข้อมูล fixture ห้ามใช้ mockup ที่วาดเอง วางตรง ไม่เอียง ไม่ติดเทป ไม่มีกรอบหนา มี title bar ได้ (ช่วยให้รู้ว่าเป็นแอป) ล้นขอบล่างโดยตั้งใจได้ ถ้าใช้ 2 หน้าจอ ให้ซ้อนกันเล็กน้อย (แบบ ModeNote) |
| **จุดเด่นทางภาพ** | หน้าต่างต้องมี "วิญญาณ" 1 จุด (A17) เช่น backdrop ภาพศิลปะที่เป็น feature จริงของแอป (Veluma: รูป keshi โผล่ในช่องว่างระหว่าง pane) หรือไฮไลต์สีเดียวที่ซ้ำกันในสองหน้าจอ (ModeNote) |
| **Wordmark** | ใช้ logo/icon จริงของแอป ตัวอักษรใหญ่ (Veluma 76px ที่ master) ใช้ฟอนต์ของแบรนด์นั้น (Veluma = Geist, ModeNote = IBM Plex Sans Thai) |
| **ข้อความ** | **ประโยคเดียว** ภาษาอังกฤษ บอกว่าแอปคืออะไร ห้ามมี eyebrow, kicker หรือ tagline ที่สอง |
| **แถบ "works with"** (ถ้ามี) | โลโก้สีเดียว + ชื่อ ขนาด ~24px วางใต้ประโยคหลัก ใช้ได้เฉพาะสิ่งที่แอปรองรับจริง ห้ามใช้สีแบรนด์ (ไม่ให้ดูเหมือนได้รับรอง) |
| **พื้น** | gradient สีของแบรนด์/แอปนั้น + grain ได้ (ข้อยกเว้นที่เจ้าของอนุมัติสำหรับปกเท่านั้น) ดึงสีจากภาพในหน้าต่างเพื่อให้นอก-ในต่อกัน |
| **ออร่าแสง** | ใช้ได้แบบ**อ่อน**: blur ~44px, opacity ~0.55 ขอบเรืองบาง 1px เจ้าของบอกว่าระดับ opacity 1 "เด่นไป" |

## 3. การปรับละเอียดที่เจ้าของเลือก

- **พื้นผิว UI ทึบพอให้อ่านง่าย** (Veluma readability 0.65): ภาพศิลปะต้องเด่นด้วย**ช่องว่าง**ระหว่าง pane ไม่ใช่ด้วยการทำ pane ใส เจ้าของบอกว่า "terminal ใสไป" เมื่อตั้งไว้ที่ 0.47
- **ภาพศิลปะ/ช่างภาพ:** เจ้าของชอบโทน artist (เงาคนหันหลัง ท้องฟ้าพลบค่ำ) ใช้ได้เมื่อเป็น content ที่แอปแสดงได้จริง และไม่ให้ใบหน้าเป็นจุดเด่น (ความเสี่ยงเรื่องสิทธิ์ภาพของศิลปินจริง เจ้าของรับทราบแล้ว)
- **ความหนาแน่น:** เต็มกรอบแบบ v3 ดีกว่าเรียบโล่ง (ดูข้อ 1)

## 4. Anti-slop checklist (ห้ามทั้งหมด)

- วงกลมไอคอนสี + เส้นโยงที่ไม่ได้เชื่อมของจริง
- tagline หลายประโยคแย่งกัน, eyebrow แบบตัวพิมพ์ใหญ่เว้นระยะ
- โลโก้ 3D มันวาวขนาดใหญ่เป็นพระเอกของภาพ
- UI ว่างหรือเป็น placeholder (`${workspaceRoot}`), screenshot ที่อ่านไม่ออก
- เอียงภาพ, ติดเทป, กรอบหนา
- ฟอนต์ที่ไม่ได้มาจากแบรนด์ (serif condensed + grotesk ปนกัน)
- รูปทรงตกแต่งที่ไม่มีความหมายในโปรดักต์ (คลื่น, วงโค้งพลังงาน)
- ตัวเลขหรือ claim ที่ verify ไม่ได้, การ upscale ภาพด้วย AI

## 5. ขั้นตอนทำงาน

1. **วินิจฉัย** ปกเดิมเป็นตารางว่า "อาการ → ทำไมดูเป็น AI → กฎใหม่"
2. **Grill เจ้าของทีละคำถาม** พร้อมคำตอบที่แนะนำ: 3 วินาทีต้องรู้อะไร → ที่มาของภาพ → ช่วงเวลาของ UI → จุดเด่นทางภาพ → ประโยคเดียว → logo/ฟอนต์ → องค์ประกอบ
3. **เขียน brief** ใน `docs/design/YYYY-MM-DD-<id>-cover-<v>-brief.md` แล้วบันทึกทุกการเปลี่ยนใจของเจ้าของ (รวมข้อยกเว้น)
4. **Pipeline** (ต้นแบบ: `design/project-covers/veluma-v4/`)
   - `capture.cjs`: เล่น scene จริงใน renderer แล้วจับภาพ 2x ได้ `canvas.png`
   - `index.html`: พื้น, wordmark, ประโยค, แถบโลโก้, ออร่า, หน้าต่าง
   - `render.cjs`: ได้ 1600×1000 PNG, WebP q88, thumbnail 240/120 (`TAG=` สำหรับเวอร์ชัน)
   - `contrast.py`: เช็ก contrast ของข้อความใน UI ที่อยู่บนภาพ (≥ 4.5:1)
5. **ส่งให้เจ้าของดูทุกรอบ** ด้วยไฟล์ชื่อใหม่ (`v4b`, `v4c`…) ห้ามเขียนทับเวอร์ชันที่เจ้าของเปิดดูอยู่
6. **ติดตั้ง:** `public/assets/project-covers/<id>-cover-vN.webp` (ชื่อใหม่ ไม่ทับของเก่า) แล้วแก้ `coverImage` + `heroMedia.image` ใน `src/data/projects/<id>.ts` ส่วน `galleryMediaRevision` จะเปลี่ยนเองตาม path
7. **ตรวจ** ที่ 1600 / 240 / 120px ในห้อง gallery และใน case hero (`/project/<id>`, 1440 และ 390)
